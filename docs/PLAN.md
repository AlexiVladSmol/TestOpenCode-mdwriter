# Markdown Editor — План и архитектура

Минималистичный редактор Markdown в духе Obsidian. Локальные `.md`-файлы,
хранилище-«vault», живое редактирование, предпросмотр, связи между заметками.

Язык: **Rust (100%)**. GUI: **egui/eframe** (нативный, без webview).
Цель — быстрая, лёгкая, офлайн-нативная утилита.

---

## 1. Согласованные решения

| Вопрос | Решение |
|---|---|
| GUI-фреймворк | **egui / eframe** (100% Rust) |
| Фронтенд (webview) | не нужен — исключён |
| Markdown-парсер | **pulldown-cmark** (GFM-опции) |
| Рендер предпросмотра | **egui_markdown** (в egui) |
| Подсветка синтаксиса | **syntect** + кастомный виджет редактора |
| Хранилище | папка-«vault» с `.md` + in-memory индекс |
| Слежение за файлами | **notify** |
| Поиск | walkdir + regex (потом `ignore`/tantivy) |
| Граф связей | **отложен** на Phase 4 (petgraph) |
| Математика (KaTeX) | **отложена** на Phase 4 |
| Целевые ОС | **Windows + Linux** |

## 2. Архитектура

### Крейт-структура (Cargo workspace)
```
project/
├─ Cargo.toml            # workspace
├─ crates/
│  ├─ app/               # eframe-приложение, окно, state, раскладка UI
│  ├─ editor/            # виджет редактора: буфер, курсор, undo/redo,
│  │                     #   подсветка (syntect), автосохранение
│  ├─ markdown/          # pulldown-cmark: заголовки, ссылки, теги, задачи;
│  │                     #   Obsidian-синтаксис ([[...]], callouts) — препроцессор
│  ├─ preview/           # рендер в egui через egui_markdown
│  ├─ vault/             # store: обход (walkdir), слежение (notify),
│  │                     #   атомарная запись, чтение/запись заметок
│  ├─ index/             # индекс: заметки, теги, исходящие/входящие ссылки
│  ├─ search/            # полнотекстовый поиск по vault
│  └─ graph/             # (Phase 4) граф на petgraph + layout
└─ docs/
   └─ PLAN.md
```

### Модель данных
```rust
struct Vault {
    root: PathBuf,
    notes: HashMap<PathBuf, Note>,
    settings: Settings,
}

struct Note {
    path: PathBuf,
    title: String,
    tags: Vec<String>,          // #tag и frontmatter tags
    links_out: Vec<LinkTarget>, // [[wikilink]] и [text](url)
    links_in: Vec<PathBuf>,     // обратные ссылки (backlinks)
    headings: Vec<Heading>,
    frontmatter: HashMap<String, Value>,
    mtime: SystemTime,
}
```

### Markdown-конвейер
1. Сырой `.md` → `pulldown-cmark` (GFM: таблицы, задачи, зачёркивание, сноски).
2. Obsidian-синтаксис (`[[wikilink]]`, `![[embed]]`, `> [!note]` callout, `#tag`)
   обрабатывается **препроцессором** перед парсером.
3. AST используется дважды:
   - для **индекса** (ссылки, теги, заголовки);
   - для **предпросмотра** — рендер в egui через `egui_markdown`.

### Живая синхронизация
- `notify` следит за vault → инвалидация заметки в индексе → `ctx.request_repaint()`.
- Автосохранение с debounce + атомарная запись (temp + rename), без потери при крахе.

## 3. Главный риск: виджет редактора

egui даёт `TextEdit` (многострочный, с undo/redo, выделением), но **без
подсветки синтаксиса**. Поэтому редактор делаем поэтапно:

- **Phase 1a** — редактирование на `TextEdit`: открыть/создать/сохранить,
  автосохранение, файловое дерево. (Функционально, но без подсветки.)
- **Phase 1b** — кастомный виджет поверх буфера: построчная отрисовка глифов
  с подсветкой `syntect`, курсор, выделение, undo/redo, нумерация строк.

Если `egui` TextEdit окажется недостаточным — используем модель «буфер текста +
собственная отрисовка» с самого начала (это дольше, но надёжнее).

## 4. Дорожная карта

**Phase 0 — каркас**
- Workspace, крейт `app`, окно eframe, «Open vault» (выбор папки).
- Коммит рабочей структуры.

**Phase 1 — базовое редактирование**
- Открыть/создать заметку, автосохранение (атомарная запись).
- Файловое дерево vault (walkdir + notify).
- 1a: редактирование на TextEdit; 1b: подсветка (syntect).

**Phase 2 — предпросмотр**
- Живой split-режим: редактор | предпросмотр (egui_markdown, GFM).
- Frontmatter, таблицы, списки-задачи, код-блоки.

**Phase 3 — навигация и связи**
- Wikilinks `[[...]]` с переходом, backlinks-панель.
- Быстрый переключатель (Ctrl+O), полнотекстовый поиск по vault.

**Phase 4 — граф и расширения**
- Граф связей (petgraph + force layout, отрисовка egui painter).
- Callouts, чекбоксы, математика, daily notes.

**Phase 5 — полировка**
- Тёмная/светлая темы, горячие клавиши, настройки, экспорт (HTML).

## 6. Критерии «минимализма» (что НЕ делаем в MVP)
- Нет облачной синхронизации, аккаунтов, телеметрии.
- Нет плагиновой системы в MVP (заложим точки расширения).
- Нет WYSIWYG-редактора — только source + live preview.
- Нет мобильных/тач-жестов в первой версии.

1. Имя приложения/бинаря (например, `mdwriter`?).

4. Нужна ли нумерация строк и «сворачивание» заголовков в Phase 1.
