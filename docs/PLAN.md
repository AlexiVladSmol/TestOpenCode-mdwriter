# mdwriter — план и архитектура

Минималистичный редактор Markdown в духе Obsidian. Локальные `.md`-файлы,
хранилище-«vault», живое редактирование, предпросмотр, связи между заметками.

Язык: **Rust (100%)**. GUI: **egui/eframe** (нативный, без webview).
Цель — быстрая, лёгкая, офлайн-нативная утилита.

Документ описывает **фактическую** архитектуру и статус работ; отступления от
исходного плана отмечены по ходу. Список мелких задач и найденных проблем —
в [FIX_PLAN.md](FIX_PLAN.md), заметки к выпускам — в
[release-notes/](release-notes/).

---

## 1. Согласованные решения

| Вопрос | Решение |
|---|---|
| GUI-фреймворк | **egui / eframe** (100% Rust), рендерер `glow` (OpenGL 2.0+) |
| Фронтенд (webview) | не нужен — исключён |
| Markdown-парсер | **pulldown-cmark** 0.13 (GFM: таблицы, задачи, зачёркивание, сноски) |
| Рендер предпросмотра | **собственный** рендерер в `crates/preview` (pulldown-cmark → egui) |
| Подсветка синтаксиса | **syntect** через `egui_extras`, кастомный `layouter` у `TextEdit` |
| Хранилище | папка-«vault» с `.md` + in-memory индекс |
| Слежение за файлами | **notify** (рекурсивно на Windows/macOS, по папкам на Linux) |
| Поиск | свой индекс в памяти + кеш результатов (без regex/внешних движков) |
| Граф связей | **petgraph** + force-направленная раскладка с «остыванием» |
| Математика | placeholder-рендер `$…$` / `$$…$$` (настоящий рендер не сделан) |
| Целевые ОС | **Windows + Linux** |
| Выбор папки vault | собственное модальное окно (системные диалоги/порталы не используются) |

## 2. Архитектура

### Крейт-структура (Cargo workspace)

Пакеты названы `mdwriter-*`, каталоги — по назначению; у всех `publish = false`.

```
crates/
├─ app/       mdwriter:        eframe-приложение: окно, UI, модалки, хоткеи
├─ vault/     mdwriter-vault:  обход (walkdir), чтение, атомарная запись,
│                              слежение (notify), проверка путей внутри vault
├─ markdown/  mdwriter-markdown: frontmatter, wikilinks, теги, wiki → markdown
├─ index/     mdwriter-index:  метаданные заметок, связи, backlinks, поиск
├─ preview/   mdwriter-preview: рендер Markdown в egui (callouts, код, задачи)
└─ graph/     mdwriter-graph:  граф связей + force-layout
```

Отдельных крейтов `editor` и `search` нет: редактор живёт в `app` (на
`TextEdit` + `syntect`), поиск — в `index` + кеш в `app`.

### Модель данных

```rust
// crates/vault
struct Vault { root: PathBuf }                       // файлы — источник истины

// crates/index
struct NoteMeta {
    title: String,
    tags: Vec<String>,        // frontmatter + инлайн `#тег` (B13)
    links_out: Vec<String>,   // цели wikilinks, как written
}

struct Index {
    notes: HashMap<PathBuf, NoteMeta>,
    contents: HashMap<PathBuf, String>,
    lower_texts: HashMap<PathBuf, LowerText>,   // нижний регистр + карта смещений (C2a)
    // производные карты: пути, stems, links, backlinks, поколение (C1/C3)
}
```

`Vault` только читает и пишет файлы; всё остальное живёт в индексе.
Поколение индекса (`Index::generation`) меняется при любом изменении и служит
ключом кешей (поиск, граф).

### Markdown-конвейер

1. `markdown::split_frontmatter` отделяет YAML-frontmatter (BOM, CRLF,
   кавычки, списки — B12).
2. `markdown::extract_wikilinks` / `extract_tags` дают цели ссылок и теги для
   индекса.
3. Для предпросмотра публичная `markdown::wikilinks_to_md` превращает
   `[[заметка|алиас]]` в обычную ссылку `[алиас](<wiki:заметка>)` (внутри
   крейта `preview` её оборачивает приватная `wiki_to_md`); дальше
   `preview::markdown` рендерит события pulldown-cmark в egui и превращает
   клики по ссылкам и задачам в `preview::Action`.
4. Экспорт в HTML использует тот же `wikilinks_to_md` и `pulldown-cmark`,
   ссылки становятся относительными `.html`-файлами.

### Индекс и синхронизация

- **B7:** `notify` будит окно (`ctx.request_repaint`) и складывает пути
  изменений; скан откладывается с дебаунсом.
- **G7a:** на Windows/macOS — одно рекурсивное слежение за корнем; на Linux
  (inotify) — по папкам, новые папки добавляются по событию создания;
  недоступные папки попадают в `skipped()` и не мешают открыть vault.
- **C3:** изменения отдельных заметок применяются точечно
  (`NoteChange` → `Index::apply`), полный `rescan` — только если изменился
  набор путей (папка, неизвестный путь); после `flush` индекс обновляется
  из буфера редактора.
- **C4:** граф пересобирается только при открытом окне, раскладка «остывает»
  и перестаёт требовать кадры.

### Сохранность данных

- Запись — `vault::store::atomic_write`: временный файл в той же папке,
  `write_all` + `sync_all`, затем `rename` с повторами (Windows: антивирус
  держит файл). Временный файл скрыт (`.имя.md.<pid>.<n>.tmp`), поэтому не
  попадает в индекс и в слежение.
- Автосохранение с дебаунсом; `Ctrl+S` — немедленно; `flush_or_copy` при
  выходе и смене vault.
- **A3:** если открытый файл изменили снаружи, а в буфере есть несохранённые
  правки, автосохранение приостанавливается и над редактором появляется панель
  конфликта: «Загрузить с диска» (правки отбрасываются), «Оставить мои»
  (файл перезаписывается буфером) или «Сохранить мои как копию» (моя версия —
  в `имя (конфликт).md`, в редакторе — версия с диска). Если файл удалён или
  переименован, заметка остаётся открытой «осиротевшей»: можно сохранить её
  снова. Копия автоматически создаётся только в `flush_or_copy` — при выходе
  и смене vault, когда записать файл не удалось.
- **A2:** ошибки не уходят в `eprintln!`, а показываются уведомлениями;
  ошибки-состояния («не удалось сохранить») живут до разрешения, обычные
  истекают (G9).

### UI

- Раскладка своя (без `egui::Panel`): верхняя панель, дерево, редактор,
  предпросмотр, разделители.
- Модалки: быстрый переход `Ctrl+O`, выбор папки (vault и экспорт), окно
  графа.
- Уведомления — правый нижний угол; конфликт и ошибка записи — полосой над
  редактором.

## 3. Виджет редактора (риск закрыт)

Исходно главным риском было отсутствие подсветки в `egui::TextEdit`.
Решение: `TextEdit` с кастомным `layouter` (syntect) и собственной
нумерацией строк — без отдельного виджета и без своего undo/redo.

## 4. Дорожная карта и статус

**Phase 0 — каркас** ✅
Workspace, окно eframe, открытие vault, коммит рабочей структуры.

**Phase 1 — базовое редактирование** ✅
Открыть/создать заметку, атомарная запись, автосохранение, дерево vault
(walkdir + notify), подсветка (syntect), нумерация строк.

**Phase 2 — предпросмотр** ✅
Сплит-режим, собственный рендерер: заголовки, таблицы, задачи, цитаты,
сноски, код-блоки, frontmatter, callouts.

**Phase 3 — навигация и связи** ✅
Wikilinks (клик, создание по клику, якоря, регистр), backlinks,
быстрый переход `Ctrl+O`, полнотекстовый поиск со сниппетами,
переключение чекбоксов задач прямо из предпросмотра (B2).

**Phase 4 — граф и расширения** ✅
Граф (petgraph + force-layout, ленивая сборка, «остывание»), callouts,
чекбоксы (отображение), placeholder математики, ежедневные заметки.

**Phase 5 — полировка** ◐ частично
Сделано: темы (System/Dark/Light/Nord), экспорт в HTML, сохранение
UI-состояния в настройках, уведомления и конфликты, поиск с кешем и
правильными сниппетами, инкрементальный индекс.

Осталось: настоящий рендер математики, переименование/удаление заметок
из дерева, картинки в предпросмотре, кликабельные внешние ссылки, зум и
перетаскивание узлов графа, запасной рендерер (DirectX/Vulkan) для машин без
OpenGL 2.0. Кандидаты — фаза F в [FIX_PLAN.md](FIX_PLAN.md).

## 5. Стек и зависимости

| Назначение | Крейт |
|---|---|

[README](../README.md).

## 6. Критерии «минимализма» (что НЕ делаем в MVP)

- Нет облачной синхронизации, аккаунтов, телеметрии.
- Нет плагиновой системы в MVP.
- Нет WYSIWYG-редактора — только source + live preview.
- Нет мобильных/тач-жестов.
- Нет системных файловых диалогов — выбор папки свой (G6).

## 7. Решённые вопросы

1. **Имя приложения/бинаря** — `mdwriter`.
2. **Формат настроек** — JSON в `~/.config/mdwriter/settings.json`
   (Windows: `%APPDATA%\mdwriter\settings.json`), не в vault.
3. **Ссылки `[[...]]` без `.md`** — поддержаны: имя файла сравнивается без
   учёта регистра и расширения, `.md`/`.MD` равнозначны.
4. **Нумерация строк** — есть; «сворачивание» заголовков — нет (не в MVP).
