# Черновик заметок к следующему релизу

Релизы временно **не публикуются**: накопленные изменения живут в `main`.
Этот файл — рабочий черновик; в момент выпуска он переименовывается в
`docs/release-notes/v<версия>.md`, и workflow `release.yml` берёт тело релиза
именно оттуда (иначе падает на `--generate-notes`).

Правило простое: **каждая правка, которую стоит упомянуть в релизе, добавляет
пункт сюда же**, вместе с ID задачи из `FIX_PLAN.md`, если он есть.

## Исправления

- **Заметки в новых папках снова замечаются (G7a).** В 0.1.2 папки,
  созданные или перенесённые в vault после его открытия, не отслеживались:
  заметки в них не появлялись в дереве и поиске до переоткрытия vault.
  Теперь на Windows и macOS система следит за всем деревом сама, а на Linux
  новые папки ставятся на слежение по мере появления. Недоступные подпапки
  по-прежнему не мешают открыть vault.
- **Уведомления больше не висят вечно (G9).** Обычная ошибка сама исчезает
  через 20 секунд (информационное сообщение — через 5). Ошибки-состояния
  («не удалось сохранить заметку») по-прежнему живут, пока проблема не решена.
  Раньше сообщение, показанное случайно, оставалось в углу до нажатия «x» и
  выглядело относящимся к более позднему действию.
- **Пустое имя заметки — не ошибка (G9).** «+» или Enter с пустым полем
  ставят курсор в поле, сообщение «Имя заметки пустое» больше не появляется.

## Изменения

- **Сохранение больше не подвешивает окно на больших vault (C3).** Раньше
  после каждого автосохранения и каждой внешней правки весь vault
  перечитывался заново (на 2000 заметках — около 0,9 с паузы). Теперь
  перечитываются только изменённые заметки (около 12 мс), поиск и обратные
  ссылки обновляются сразу после сохранения, а граф пересчитывается, только
  пока его окно открыто.
- **Поиск по vault стал точнее и дешевле (C2).** Совпадения в заголовке
  заметки показываются выше совпадений в тексте; сниппет больше не «съезжает»
  в текстах с `İ` и знаком Кельвина `K` (смена регистра меняла длину строки).
  Результаты кешируются и пересчитываются только при смене запроса или
  индекса, а не в каждом кадре.

## Внутреннее (не для пользователя)

- CI зелёный на Ubuntu и Windows; релизный workflow проверяет совпадение тега
  и версии из `Cargo.toml`.
